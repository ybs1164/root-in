# 미니맵 디자인 개선 계획 — 추상화 단계를 "예쁜 지도"로

> 2026-10-19 작성. 대상: TODAY(날짜 화면) 핑 아래 미니맵과 공유 카드의 같은 그림.
> 앞선 작업: [plan-minimap-levels.md](plan-minimap-levels.md)(형태 × 거리 두 축 — 구현됨, 미커밋).
> 작업 번호 **D1~D8**로 참조한다.

## 0. 한 줄 원칙

**지도는 무대, 주인공은 핑과 선이다.** 땅은 조용히 뒤로 물러나고, 하루의 동선(선·핑·이름)이 한눈에 읽혀야 한다.
모든 결정은 이 문장으로 판정한다.

## 1. 지금 상태 (2026-10-19, 375px에서 확인)

샘플: 성수 4곳(어니언·갈비집·대림창고·서울숲) + 한남 와인바 1곳(한강 건너 약 5km). 거리 단계 '중간'.

| 형태 | 보이는 것 | 문제 |
|---|---|---|
| 덩어리 | 핑마다 원 + 핀 머리까지 막대 → 알약(캡슐) 모양 섬 2개 | 땅이 아니라 UI 버튼처럼 보임. 섬 모양이 핀 모양을 그대로 따라 해서 기계적. |
| 거리 | 덩어리 + 모든 섬에 같은 -18° 격자 | **가짜 거리**: 실제 길 방향과 무관한 격자(“지도로 거짓말하기”). 모든 섬이 같은 무늬라 반복이 눈에 띔. |
| 지도 | 둥근 땅 하나 + 그림자 | 가장 보기 좋음. 다만 안이 비어 있어 단조롭고, 핀·선과 땅이 같은 색 계열이라 선이 묻힘. |
| 상세 | 실제 읍면동 도형 + 흰 틈 경계 | ① 땅이 그림 상자의 약 55%×25%만 차지(기울임 0.55로 납작) ② 행정 경계의 흰 그물이 산만함 ③ **한강이 없음** — 성수·한남을 가르는 진짜 경계가 안 보이고, 사람이 모르는 동 경계만 보임 ④ 선이 땅(강조색 40%)에 묻힘 ⑤ 이름 충돌(서울숲 핀이 '대림창고'를 가려 '대림'만 보임). |

공통:
- **전경–배경 대비 부족**: 땅 `mix 0.4~0.42`, 핀·선 `accent 100%` — 같은 색상(hue)에 명도 차이만 조금이라 선이 땅 위에서 사라진다.
- 기울임은 모든 형태에 같은 값, 먼 쪽·가까운 쪽 차이(공기 원근)가 없어 깊이감이 약하고, 두께(옆면)가 없어 "판"이 아니라 "그림자 진 스티커"로 보인다.
- 이름표는 탐욕 배치(`placePingLabels`) 한 번 — 핑이 몰리면 겹침이 남는다. 땅 위 글자에 바탕 번짐(halo)이 없다.

데이터: 지도 원본 `public/korea/base`(`BaseMap`)에 **땅(물은 땅이 없는 곳)·공원·도로 5등급**이 이미 있다(`domain/baseMap.ts`, `koreaMapService`). 상세는 지금 행정구역(`admin`)만 쓰고 있다.

## 2. 방법론 → 이 앱의 규칙

| 출처 | 핵심 | 우리 규칙 |
|---|---|---|
| **Eduard Imhof**, *Cartographic Relief Presentation* (1965/1982) — 색의 규칙 | 넓은 면은 회색 기운의 차분한 색, 순수하고 밝은 색은 작은 면·강조에만. 공기 원근: 멀수록 대비가 줄고 밝아짐. | 땅은 저채도 고명도, 강조색 100%는 핀·선에만(**R1**). 기울인 땅의 먼 쪽(위)은 더 밝고 대비가 낮게(**R5**). |
| **Imhof**, *Positioning Names on Maps* (1975) | 이름은 점의 오른쪽 위가 가장 좋고, 선·다른 기호와 겹치지 않으며, 무엇의 이름인지 모호하지 않게. | 이름 후보 위치를 4→8곳으로, 겹침 0을 하드 조건으로(**R6**). 땅 위 글자는 바탕색 번짐. |
| **Kevin Lynch**, *The Image of the City* (1960) | 사람이 기억하는 도시 = 길(paths)·경계(edges)·구역(districts)·결절점(nodes)·랜드마크. | 상세에서 그릴 것은 **강·하천(경계)·큰길(길)·공원(구역)**. 행정 경계는 사람이 인지하는 경계가 아니므로 지우거나 아주 흐리게(**R3**). |
| **McMaster & Shea**, *Generalization in Digital Cartography* (1992) / Monmonier, *How to Lie with Maps* | 일반화 연산: 선택·단순화·매끄럽게·합치기·과장·이동. 없는 정보를 지어내지 않기. | 형태 단계 = 일반화 사다리로 다시 정의(§3). 가짜 격자 같은 **지어낸 디테일 금지**(**R4**). |
| **Agrawala & Stolte**, *Rendering Effective Route Maps* (SIGGRAPH 2001, LineDrive) | 길 안내 지도는 길이를 왜곡해도 되지만 **방향·순서·위상**은 지킨다. | 거리 축(균등~실제)이 이미 이 원칙. 땅도 같은 휨(`bendField`)을 따르게 유지, 왜곡된 단계에서는 "축척 없는 그림"임을 숨기지 않음(축척 막대 없음). |
| **Edward Tufte**, *Envisioning Information* (1990) | 층 나누기(layering & separation), "1+1=3"(두 선 사이에 생기는 의도치 않은 형태), 가장 작은 유효 차이. | 행정 경계의 흰 틈 그물 = 1+1=3 잡음 → 없앰. 층은 명도 단계 3~4개로만 구분(**R2**). |
| **Cynthia Brewer**, *Designing Better Maps* (2005/2015) | 전경–배경, 시각 위계, 선 테두리(casing). | 경로 선은 바탕색 테두리 + 진한 잉크(**R1**). 대비를 숫자로 검사(테스트). |
| **Jacques Bertin**, *Sémiologie graphique* (1967) | 시각 변수: 위치·크기·명도·색상·질감·방향·모양. 순서는 명도로. | 땅·물·공원은 **명도/색상** 차이, 핀 순서·최근 핑은 **크기**(이미 있음). 질감은 지도엔 안 씀(꾸미기 배경 패턴과 충돌). |
| **Harry Beck / Maxwell Roberts**, *Underground Maps After Beck* (2005) | 도식 지도: 45° 단위 선, 고른 간격. | (선택) 거리 '균등'과 묶은 새 형태 **노선도** — §6 결정 항목. |

규칙 요약
- **R1** 강조색 100%는 핀·선만. 땅은 강조색 10~18%를 바탕에 섞은 저채도. 선은 진한 잉크(`--route`) + 바탕색 테두리.
- **R2** 명도 층은 많아야 4개: 그림자 < 물 < 땅 < 공원/길(땅보다 살짝 밝게 파냄).
- **R3** 상세는 행정 경계 대신 물·공원·큰길. 핑이 있는 동만 아주 옅게 구역 강조(선택).
- **R4** 지어낸 디테일 금지. 추상 단계는 "없애기·합치기·매끄럽게"로만 단순해진다.
- **R5** 기울인 땅은 두께(옆면) + 먼 쪽 밝게 + 그림자.
- **R6** 핀·이름·선은 서로 가리지 않는다(겹침 점수 0이 목표, `pingOverlap`).
- **R7** 땅이 그림 상자를 넉넉히 채운다(기울인 뒤 기준 폭 80% 이상).

## 4. 디자인 변경안

### 4.1 색과 층 (모든 형태 공통) — D1
- 지도 색을 `MapFill { mix, dark }` 즉석 값에서 **역할 이름**으로: `land`, `landSide`(옆면), `water`, `park`, `road`, `shadow`. 각 역할은 테마 토큰에서 `color-mix`로 유도(테마 18종을 따로 칠하지 않음):
  - `land` = accent 14% over `--surface` (지금 40% → 크게 낮춤)
  - `landSide` = land를 `--mask-hide` 쪽으로 12%
  - `water` = accent 28% + 약간 어둡게 (땅보다 한 단계 진하게 — 물이 "빈 곳"으로 읽히게)
  - `park` = 공통 녹색 계열 토큰 하나 추가(`--map-park`, 테마별 다크 값) — 결정 필요(§7)
  - `road` = `--surface` 쪽으로 밝게 파냄
- 경로 선(`pings__line`): `--route` 잉크 + 바탕색 테두리 2px(Brewer의 casing). 핀은 강조색 그대로 + 아주 얇은 바탕색 외곽(정적 SVG라 지도 마커의 성능 문제와 무관).
- 이름 글자에 바탕색 번짐(루트 정류장 이름과 같은 방식) — 땅 위에서도 읽히게.
- `styles.test.ts` 규칙에 맞게 새 색은 모두 `:root` 토큰.

### 4.2 형태 단계 = 일반화 사다리 — D2·D3·D4

| 단계 | 일반화 연산 | 새 모습 |
|---|---|---|
| 없음 | — | 그대로 |
| **덩어리** | 합치기 + 매끄럽게 | 캡슐 대신 **유기적인 섬**: 핑마다 가우스 봉우리를 더한 장(field)의 등고선(marching squares) 하나 — 가까운 핑은 자연스럽게 이어지고 먼 묶음은 따로 섬(묶음 기준은 지금처럼 미터 `CHUNK_GAP_M`). 핀 머리 여유는 봉우리를 위로 늘린 타원으로. |
| **거리 → '길'** | 선택(경로만) | 가짜 격자를 없애고, **그날의 동선 자체를 길로**: 땅 위에 구간을 따라 바탕보다 밝은 넓은 띠(길)를 파냄. 실제 큰길(도로 1~2등급)이 있으면 그 섬 안에서만 2~3개 더(선택·단순화). |
| **지도** | 합치기 + 매끄럽게 + 과장 | 지금 모양 유지 + 옆면 두께·공기 원근(4.3). 안쪽에 아무것도 지어내지 않음. |
| **상세** | 선택 + 단순화 | 행정 경계 그물 대신 **물·공원·큰길**(`BaseMap`): 땅 실루엣은 지금처럼 핑 주변 동 덩어리로 자르되(`lumpAreas`), 그 안을 강(땅 없음)·공원(녹색)·큰길(밝은 선)로 채움. 행정 경계는 기본 끔. 데이터가 없으면 지금처럼 '지도'로 대체(거리 배치는 그대로). |

- 단순화 공차는 그림 크기 기준으로 한 번 정하고(지금 `simplify(…, 0.0007)`), 매끄럽게는 Chaikin 2회 정도 — 상세가 "각진 행정 도형"이 아니라 "그린 지도"로 보이게.
- 공원·물 도형 수는 상한(예: 면 60개, 길 30개)을 두고 작은 면은 버림(선택 연산) — 공유 이미지·저사양 폰 비용 보호.

### 4.3 기울임과 디오라마 — D5
- 기울임 `TILT` 0.55 → 0.68 정도로 덜 납작하게(상세가 띠처럼 보이던 문제).
- **옆면 두께**: 땅 윤곽을 아래로 `dy` 만큼 내린 복사본을 `landSide` 색으로 먼저 칠함 → 판 두께. 그림자는 그 아래 더 멀리·흐리게.
- **공기 원근**: 땅 위에 위(먼 쪽)→아래(가까운 쪽) 세로 그라데이션 마스크로 먼 쪽 명도를 살짝 올림(SVG `linearGradient`, 캔버스 `createLinearGradient` — 두 곳 같은 값).
- 맞춤: 기울인 **뒤** 경계 상자 기준으로 그림 상자 폭 80~85%를 채우도록 배율 결정(R7). 위아래 여백은 이름표 높이만큼.

### 4.4 이름표 — D6
- `placePingLabels` 후보를 8방향(오른쪽 위 우선 — Imhof)으로 넓히고, 핑 수가 적으면(≤7) 모든 조합을 점수로 비교, 많으면 지금 탐욕 + 몇 번의 교환(국소 탐색). 점수 = 겹침 면적 + 선과 겹침 + 위치 선호 벌점.
- 그래도 겹치면: 시간 줄을 먼저 숨기고(가장 최근 핑 제외), 그다음 이름을 말줄임.
- `bestBearing`(지도 회전)이 이미 겹침을 줄이는 쪽으로 돌리므로 새 점수 함수를 같이 씀.

### 4.5 움직임 — D7 (선택)
- 지금: 0.5초 페이드. 후보: 땅이 납작한 상태에서 기울어지며 서는 0.4초 연출 후 핑이 떨어짐(`stop-drop`) — 동작 줄이기 설정이면 없음. 정적 공유 이미지에는 영향 없음.

## 6. 성능·제약

- 날짜 화면은 SVG 한 장, 공유 이미지는 캔버스 — **같은 `MapPart` 목록**을 두 렌더러가 그리는 지금 구조 유지(그림이 다르면 안 됨).
- 상세는 BaseMap 타일까지 받아야 하므로 `terrainService` 캐시에 함께 넣고, 실패하면 reject 없이 지금처럼 '지도'로 대체.
- 흐림 필터는 그림자 한 겹만(저사양 폰). backdrop-filter 금지 규칙과 같은 이유.
- 데이터는 국내만, 원본을 공유 링크에 싣지 않음(그림은 받는 쪽에서 다시 그림 — 받은 하루 링크는 지금 안 열림).

## 7. 정할 것 — 2026-10-19 모두 권장안으로 결정

1. **공원 색**: 테마와 무관한 녹색 토큰 하나(`--map-park`, 지도 앱과 같은 약속) vs 강조색 계열로만(테마 통일감). 권장: 녹색 — 공원이 공원으로 읽히는 게 우선(Lynch).
2. **'거리' 단계 처리**: 구간 띠 '길'로 바꾸기(권장) vs 단계 삭제(없음·덩어리·지도·상세 4단계).
3. **상세의 행정 경계**: 완전히 끔(권장) vs 핑이 있는 동만 옅게 구역 표시.
4. **노선도(Beck식 45° 도식) 형태 추가 여부**: 하루 동선을 "지하철 노선도"처럼 — 재미있지만 범위가 커서 이번엔 보류 권장.
5. **기울임**: 모든 형태 같은 값(권장) vs 상세만 덜 기울임.
