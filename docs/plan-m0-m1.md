# root-in (구 goodRoot) — M0 ~ M1 실행 계획

## 제품 한 줄

> **내가 다녀온(또는 짜둔) 코스를 링크 하나로 공유하고, 받은 사람은 지도에서 그대로 보고 저장한다.**

- **공유자**: 데이트 코스·여행 동선·맛집 투어를 정리해서 보여주고 싶은 사람
- **수신자**: 링크를 받아 "어디를 어떤 순서로 가면 되는지" 바로 보고 싶은 사람 (앱 설치·로그인 없이)
- **핵심 단위는 "코스"**: A→B 두 점이 아니라 **순서가 있는 장소 2~10곳** + 장소별 한 줄 메모 + 이동수단

### 지금 코드와의 차이
| 현재 | 목표 (M1 끝) |
|---|---|
| 하드코딩 도시 4곳 (`data/places.ts`) | 카카오 장소 검색 (카페·식당·명소) |
| 출발지 → 도착지 1구간 | 스톱 N개 순서 있는 코스 |
| 자동차 경로 (OSRM demo) | **직선 연결 + 추정 시간 + 카카오맵 길찾기 링크** (라우팅 API 없음) |
| MapLibre + CARTO | **카카오맵 JS SDK** (키 없으면 MapLibre로 대체) |
| 데스크톱 사이드바 | **모바일 우선**: 전체 화면 지도 + 하단 시트 |
| 공유 링크 v1 (2점) | 공유 링크 v2 (N점) — **v1 링크도 계속 열림** |
| localStorage `travel-routes:v1` | `courses:v2` + v1 데이터 자동 이전 |

M1까지는 **백엔드·로그인 없음**. 저장은 localStorage, 공유는 URL 해시. (M2에서 교체 — 인터페이스는 이미 분리돼 있음)
서비스 범위는 **국내 한정** (해외 코스는 M3 이후 별도 지도 제공사로 검토).

### 지도·장소 결정 (2026-09-28)
- 지도: 카카오맵 JS SDK (`VITE_KAKAO_JS_KEY`). 키가 없거나 로드 실패 시 MapLibre + CARTO로 대체해 개발·프리뷰가 키 없이도 돌게 한다.
- 장소 검색: 카카오 JS SDK `services.Places.keywordSearch` (REST 키를 프론트에 노출하지 않기 위해). 대체: Photon.
- 이동 경로: 길찾기 API를 쓰지 않는다. 국내 도보·대중교통 길찾기 API는 공개돼 있지 않거나 유료이고, 안내는 카카오맵/네이버지도가 이미 잘한다.
- 공유: 링크 복사 + Web Share API. 카카오톡 공유 SDK는 1.8에서.

## M1 — 실제 장소로 코스 만들고 공유 (1.5~2주)

### 1.1 도메인 모델: `TravelRoute` → `Course` (1일)
```ts
type CourseTheme = 'date' | 'trip' | 'food' | 'etc';
type TravelMode = 'walk' | 'transit' | 'drive';

interface PlaceRef {           // 기존 + 필드 2개
  id: string;                  // 'kakao:123' | 'osm:N12345' | 'pin:<lon>,<lat>'
  name: string;
  center: [number, number];
  category?: string;           // 'cafe' | 'restaurant' | ...
  address?: string;
}
interface CourseStop { place: PlaceRef; memo?: string }   // memo ≤ 120자
interface Course {
  id: string; userId: string;
  title: string; theme: CourseTheme; travelMode: TravelMode;
  stops: CourseStop[];         // 2 ≤ length ≤ 10
  note?: string; sharedBy?: string; createdAt: string;
}
```
- 순수 함수 모듈 `domain/course.ts`: `validateCourse`, `moveStop`, `removeStop`, `addStop`(최대 10), `defaultTitle`
- `CourseRepository` (기존 인터페이스 형태 유지) + localStorage `goodroot:courses:v2`
- **마이그레이션**: `travel-routes:v1`의 각 항목 → stops 2개, theme `'trip'`, mode `'drive'`. 1회 실행 후 v1 키 삭제.

### 1.2 장소 검색 서비스 (1~2일)
- 인터페이스 `PlaceSearchService { search(query, { near, signal }): Promise<PlaceRef[]> }`
- 기본 구현: **카카오 Places** (JS SDK `services`, 현재 지도 중심 `location` 가중치). id는 `kakao:<id>`, 카테고리·도로명 주소 포함
- 대체 구현: **Photon** (키 없음). 카카오 키가 없거나 SDK 로드 실패 시 사용
- 입력 디바운스 300ms, 이전 요청 무시, 결과 최대 10개
- 품질 점검 쿼리: `성수 카페`, `을지로 노가리`, `해운대`, `익선동`, `망원시장`, `스타벅스 강남`

### 1.3 지도 상호작용 (1~2일)
- 검색 결과 클릭 → 지도 이동 + 미리보기 마커 + "코스에 추가"
- 지도 길게 누르기/우클릭 → 역지오코딩으로 임의 지점 추가 (이름 없으면 "지정한 위치")
- 코스 스톱에 **번호 마커** (1, 2, 3 …), 클릭하면 이름·메모 팝업

### 1.4 코스 편집 UI (2~3일)
- 사이드 패널: 제목, 테마 칩(데이트/여행/맛집/기타), 이동수단 토글, 스톱 리스트
- 스톱: 위/아래 이동 버튼, 삭제, 한 줄 메모 (드래그앤드롭은 M1 이후)
- 구간별 거리·시간 + 총합 표시 ("도보 12분 · 850m")
- 저장된 코스 목록: 테마 뱃지, 스톱 수, 공유받은 코스 표시
- 모바일(375px): 사이드바 → 하단 시트

### 1.5 구간 추정 + 길찾기 링크 (0.5~1일)
- `domain/geo.ts`: 직선거리(하버사인) × 우회계수로 구간별 거리·시간 추정. 표시는 항상 "약 N분"
- 이동수단 `walk | transit | drive` (도보 기본)
- 구간마다 카카오맵 길찾기 링크 `https://map.kakao.com/link/by/{walk|traffic|car}/A,lat,lng/B,lat,lng`
- 지도에는 스톱 사이 직선(점선) 폴리라인 + 번호 마커
- (삭제) OSRM/FOSSGIS 라우팅 — 필요해지면 M3에서 카카오모빌리티 등 검토

### 1.6 공유 링크 v2 (1~2일)
- 와이어 포맷 `v: 2` — `s: [{i,n,c,k?,m?}]`, `h` 테마, `x` 이동수단. 좌표는 소수 6자리로 반올림
- `decodeSharedRoute`는 **v1과 v2 모두 디코드** (v1 → 스톱 2개 코스)
- 이동수단 `x`는 `walk|transit|drive`
- 도시 목록이 없어지므로, 링크의 장소를 카탈로그로 다시 확인하던 방식 대신 **좌표 범위·문자열 길이 검증**만 수행 (현재 `parsePlace` 방식 확장)
- 스톱 10개 + 메모까지 넣어도 토큰 4000자 이하 → 초과하면 메모부터 자르고 안내
- 공유 카드: 번호 목록, 테마, 총 소요시간, "지도에서 보기 / 내 코스에 저장"
- 공유 문구(`formatShareText`): `1. 카페 어니언 → 2. ... ` 형태

### 1.8 카카오톡 공유 (0.5일)
- 카카오 JS SDK `Kakao.Share.sendDefault` (피드 템플릿: 코스 제목, 스톱 목록, 링크). 키 없으면 버튼 숨김

### 1.7 정리 (0.5일)
- `data/places.ts`, 기존 출발/도착 select UI, `TravelRoute` 타입 제거
- `recommendationService`는 코스 기준으로 키만 바꿔 유지 (스톱 id 목록 해시) — 실제 추천은 M3

### 추가: 하루 경로 기록(다이어리) + 위시리스트 (2026-09-28)
정보량은 셋로그처럼 최소로: 하루 = **시간 · 장소 · 한 줄** 타임라인.
- 지도 우상단 📔 버튼 → 처음엔 바로 오늘 기록, ←로 목록(기록 / ★)
- 추가: "📍 지금 여기"(브라우저 위치) 또는 검색. 오늘이면 현재 시각 자동 입력, 시간 수정 후 자동 정렬
- **자동 저장** (저장 버튼·변경 확인 없음). 장소를 모두 빼면 그날 기록 삭제
- 제목·기분·이동수단·일기 본문·거리/시간 추정·주소는 UI에 없음 (타입·링크 디코더는 호환을 위해 남김)
- 저장: `goodroot:diaries:v1`. 위시리스트는 별도 `goodroot:wishlist:v1` 스냅샷 — 원본을 지워도 남음
- 공유 링크 `#diary=<token>` (코스 `#share=`와 별도). 공유 시트는 "보내기 / 링크 복사"만
- 받은 하루: 타임라인 + "☆ 위시리스트에 저장" 하나

### M1 완료 기준 (Definition of Done)
1. `npm run check` 통과, `m1-acceptance.test.ts`에 `todo` 0개
2. **시나리오 A (공유자)**: "성수" 검색 → 카페·식당·공원 3곳 추가 → 순서 변경 → 도보 → 테마 "데이트" → 저장 → 링크 복사
3. **시나리오 B (수신자)**: A의 링크를 시크릿 창에서 열기 → 같은 순서의 번호 마커와 경로, 메모 표시 → "내 코스에 저장" → 새로고침해도 남아 있음
4. **호환성**: 기존 v1 공유 링크가 스톱 2개 코스로 열리고, 기존 저장 경로가 코스 목록에 보임
5. 375px 폭에서 A, B 모두 가능 (모바일 우선 UI)
6. 외부 API 실패(오프라인)나 카카오 키 없음에도 앱이 멈추지 않음 (대체 지도·검색, 실패 메시지 표시)

### M1에서 하지 않는 것
로그인/서버 저장, 추천 피드, 드래그 정렬, 사진, 영업시간·가격, 실제 이동 경로(길찾기), 해외 지도, 코스 편집 후 링크 갱신(링크는 스냅샷)

## 리스크와 결정이 필요한 것
| 항목 | 내용 | 기본안 |
|---|---|---|
| 카카오 키·도메인 | 키 발급과 도메인 등록 전에는 카카오 지도·검색이 동작하지 않음 | 대체 구현(MapLibre + Photon)으로 개발, 키는 `.env.local` |
