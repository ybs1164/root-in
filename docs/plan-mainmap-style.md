## 0. 한 줄 원칙

**같은 지도 언어, 다른 무대.** TODAY 미니맵이 예쁜 이유(조용한 땅·물·공원·큰길, 경계 그물 없음, 진한 선과 테두리, 판의 두께)를 본 지도에도 쓰되, 본 지도는 끝없이 끌고 확대하는 지도라 **한 장짜리 그림에서만 통하는 것(외곽선 자르기·기울임·핀 떼어 놓기·거리 펴기)은 가져오지 않는다.**

## 3. 층 (아래에서 위로)

1. **물** — 화면 바탕(`--map-water` 역할). 국내 밖은 지금처럼 덮개(cover)가 가림.
2. **땅** — `BaseMap.land`, 단계별 타일(`koreaMapService`가 축척으로 고름). 작은 구멍(연못 부스러기)은 미니맵 `MIN_POND`처럼 화면 px 기준으로 메움.
3. ~~(선택) 떠 있는 판~~ — 안 함(M7 결정).
4. **구역 색** — 지금의 `parts`(가운데 범위가 나뉜 조각)는 땅 위에 강조색 몇 % 얹은 **옅은 틴트**로만, `others`는 안 칠함(땅 그대로). 조각 사이 틈은 땅색 실선으로 **아주 가늘게**(1px 미만, 확대 깊으면 길 단계라 실제 길이 대신함).
5. **공원** — `BaseMap.parks`, 녹색 역할.
6. **길** — `BaseMap.roads`, 축척별 등급(`roadTierVisible`·`roadWidthPx` 이미 있음). 색은 땅보다 밝게(`--mini-road`처럼 `--surface`), 1등급만 살짝 진한 테두리. 미니맵은 1등급만 쓰지만 본 지도는 확대할수록 등급을 늘림.
7. **구역 이름** — 그대로, 바탕색 번짐 추가.
8. 핀·정류장·선(`StopLines`, 테두리 추가)·내 위치·그룹 핑 — 그대로.

## 4. 엔진별 방법

- **MapLibre**: GeoJSON 소스 + `fill`/`line` 레이어(물은 `background`, 땅·공원 `fill`, 길은 등급별 `line` — 폭은 줌 표현식으로 `roadWidthPx`와 같은 값). `refreshColors`가 새 레이어도 다시 칠함. 길 데이터가 크면 등급별로 소스를 나눠 줌에 따라 `setData`.
- **카카오**: 타일을 다시 칠할 수 없어 지금처럼 덮개 위에 SDK 객체를 얹음. 땅·공원은 `Polygon`(지금 `reshape`처럼 객체 재사용), 길은 `Polyline`. 객체 수가 성능의 전부라 **상한**(예: 면 300 · 길 400, 넘으면 작은 것·낮은 등급부터 버림)과 화면 밖 버리기. 그래도 끌 때 버벅이면 §6-2의 캔버스 오버레이 안.
- **계산 위치**: 땅·공원·길 고르기·단순화·구멍 메우기는 이미 있는 area worker(`services/areaMap.worker.ts`)에 넣어 행정구역과 **한 번에** 보냄(`AreaUpdate`에 `base` 추가) — 메인 스레드는 그리기만. `useBaseMap`은 지우거나 worker 경유로 바꿈.
- 지도 SDK 호출은 계속 `src/map/` 안에만(작업 규칙).

### M11 — 덩어리를 예쁘게: 곡선·합치기·네 톤·그림자 (2026-10-22)

방법론 조사(곡선 도식화 van Goethem·Meulemans·Speckmann, 일반화의 합치기 amalgamation, 4색 지도, Zenly·Apple 지도·Airbnb/당근 동네 지도·Kurzgesagt 일러스트 지도) 뒤 셋 다 적용:
1. **이어지는 곡선 + 작은 동 합치기**: 동·해안 윤곽을 단순화한 점을 지나는 한 곡선(구심 Catmull-Rom `domain/curves.ts` `smoothClosed`, 3px마다 — 곧은 변은 9px마다 점을 더해 곧게 둠, 안 그러면 모퉁이의 접선 때문에 긴 변이 24px까지 휨). 동은 단순화 2.5px 뒤 곡선, 해안은 M10의 둥근 모퉁이 대신 곡선. 화면에서 22px 정사각형보다 작은 동은 가장 많이 닿은 이웃(되도록 큰 쪽)과 합쳐 그림(`amalgamate`, 이름은 큰 쪽만).
2. **네 톤**: 가운데 동마다 강조색 8·12·16·20% 중 하나(`--map-tone-0..3`, `PART_TONES`), 이웃끼리 다르게(많이 닿은 동부터 욕심쟁이 칠하기 `toneParts`; `AreaShapes.partTones`) — 그래서 틈은 2px → 1.5px씩(최소 2.5px)으로 가늘게. MapLibre는 `match`로, 카카오는 폴리곤마다 색·불투명도.
3. **한 덩어리 그림자**: 가운데 동을 틈을 메워 하나로 합친 윤곽(`partsOutline`) 바깥에만 부드러운 그림자 — MapLibre는 흐린 선(`area-shadow`, 아래로 3px, 폭 8·blur 6·불투명도 0.2), 카카오는 흐림이 없어 윤곽을 3px 내린 옅은 면. 동마다 그림자를 주면 경계 그물이 되살아나던 M7 실험의 대안. 경로가 보이면 틴트와 함께 빠짐.

- 헤드리스에서는 4장에 1장꼴로 옛 화면(덜 그린·확대된 프레임)이 찍혔다. 앱 상태(가운데·줌·MapLibre CSS)는 맞았으므로 캡처 쪽 문제로 보고, 영역 소스가 3초 조용할 때까지 기다림 → 1px 오가는 이동 → `render`·`idle` → 버리는 캡처 한 장 → 진짜 캡처. 그래도 가끔 남아서 나쁜 장은 그 상태만 다시 찍음(데스크톱 yangpyeong-gu는 아직 옛 화면 — M8 전에 다시).
- 확인 필요(앱 버그일 수 있음): 앱 안 미리보기에서도 시군구 축척으로 맞춘 뒤 영역이 도착했는데 `triggerRepaint` 전까지 화면이 비어 있던 적이 한 번 있었다. 지도가 안 움직일 때 `setData`만으로 다시 그려지는지 M3에서 같이 본다.

### M8 결과 (2026-10-20)

찍은 것: `npm run shots -- mainmap`(기본)과 `SHOTS_SCHEME=dark npm run shots -- mainmap`(다크 — 이번에 넣은 스위치, 파일 끝에 `-dark`), 48장 모두 성공. 모은 것 `ui-shots/mainmap-m8-{mobile,desktop}.png`·`mainmap-m8-dark-{mobile,desktop}.png`, 전(M0)은 `mainmap-before*.png`. 헤드리스의 옛 프레임 캡처가 이번에도 기본 5장·다크 7장쯤 섞여 있어 그 장들은 판단에서 뺌(앱 상태는 맞음 — M0 참고).

보이는 것(전 → 후):
- **물**: 한강·중랑천·남한강이 시군구·읍면동·블록 모든 축척에서 물로 보임(전에는 어디에도 없었음). 양평 읍면동에서 남한강이 화면을 가로지름.
- **경계 그물**: 시군구 축척 화면 전체를 덮던 흰 틈 그물이 없어지고, 가운데 동만 옅은 틴트 + 가는 밝은 틈. 경로가 뜨면 틴트·이름이 같이 빠짐(M4·M6).
- **길·공원**: 블록 축척이 빈 면에서 실제 길·공원이 있는 지도가 됨. 성수 블록·종로 블록에서 길 폭이 넓은 편(1등급 최대 34px)이라 '길 지도' 느낌이 강함.
- **다크**: 물·공원·땅이 같은 순서로 구별되고 이름도 읽힘. 다만 다크에서는 길(`--map-road` = 바탕색)이 땅보다 **어두운 홈**으로 보임(기본에서는 밝은 선) — '파낸 길'로 읽혀 일부러 둠, 밝은 선이 낫다면 다크만 `--map-road`를 땅보다 밝게.
- 카카오: 이 PC에서는 카카오 SDK가 안 떠서(M5) 화면·프레임 모두 못 봄 — 남은 일.

끌기 프레임: 아래 '프레임 비교'(같은 날 M0 코드를 worktree로 띄워 번갈아 3번).

남은 것·후속 후보: ① 카카오 화면·프레임(키가 도는 브라우저나 안드로이드) ② 시군구 축척의 2등급 길 밀도(25m/px 위에서 2등급 숨기기 후보) ③ 블록 축척 길 폭 상한 ④ 다크 길 색 ⑤ 헤드리스 캡처 문제 때문에 shots 장면은 가끔 다시 찍어야 함.

## 6. 정할 것

1. **행정 구역 표시 세기** — ✅ 2026-10-20 결정: **옅은 틴트 + 가는 틈**(구역 나누기·이름 기능은 살리고 그물만 조용히). 다른 안: 완전히 끄고 이름만(미니맵과 똑같음, 대신 확대할 때 동이 나뉘는 느낌이 사라짐) / 지금 그대로(물·공원·길만 더함).
2. **카카오에서 그리는 방법** — 권장: **SDK 객체 + 상한**(지금 구조 그대로). 다른 안: 한 장 캔버스 오버레이에 직접 그리기(빠르지만 카카오 지도 이동과 맞추는 코드가 새로 필요, 확대 중 흔들림 위험).
3. **떠 있는 판(M7)** — ✅ 2026-10-20 결정: 안 함(실험 결과는 M7 줄). 판·안개는 TODAY 미니맵에만.
4. **카카오 타일을 아예 가릴지** — 지금도 덮개로 가리고 있음. `BaseMap`이 있으면 카카오 타일은 끝까지 안 보이게 유지(권장) vs 블록보다 깊은 확대에서만 카카오 타일을 비춰 건물·상호를 보여 줌.

## 7. 하지 않는 것

- 본 지도 기울이기(pitch)·외곽선 자르기·핀 떼어 놓기·거리 펴기 (§2).
- 테마별 지도 색 — 지도는 언제나 기본(+ 다크) 테마라는 규칙 유지. 역할 색을 토큰에서 유도해 두면 나중에 바꾸기는 쉬움.
- 건물 하나하나, 지형 음영.
