# 본 지도에 TODAY 미니맵의 꾸밈 옮기기

> 2026-10-20 작성. 대상: 📍 핀 탭의 전체 화면 지도(`CourseMap` — MapLibre·카카오 둘 다)와 We Now 그룹 지도.
> 출발점: [plan-minimap-design.md](plan-minimap-design.md)(D1~D8 색·층·기울임·이름표), [plan-minimap-silhouette.md](plan-minimap-silhouette.md)(S0~S9 외곽선).
> 작업 번호 **M0~M8**로 참조한다.

## 0. 한 줄 원칙

**같은 지도 언어, 다른 무대.** TODAY 미니맵이 예쁜 이유(조용한 땅·물·공원·큰길, 경계 그물 없음, 진한 선과 테두리, 판의 두께)를 본 지도에도 쓰되, 본 지도는 끝없이 끌고 확대하는 지도라 **한 장짜리 그림에서만 통하는 것(외곽선 자르기·기울임·핀 떼어 놓기·거리 펴기)은 가져오지 않는다.**

## 1. 무엇이 다른가 (2026-10-20)

| | TODAY 미니맵 | 본 지도 지금 |
|---|---|---|
| 바탕 | 물(`--mini-water`) 위에 땅 — 강이 강으로 보임 | `--map-bg` 단색. **한강이 없음** |
| 면 | 땅·공원(녹색) 실제 `BaseMap` | 행정구역 도형 두 색(`--map-area`·`--map-area-other`) |
| 경계 | 행정 경계 안 그림(R3) | 구역 사이 흰 틈 = 경계 그물(`ui-shots/9-seongsu-map.png`) — 미니맵 계획이 '1+1=3 잡음'이라 지운 바로 그것 |
| 길 | 1등급 큰길만 바탕보다 밝은 선 | 깊이 확대해야(구획·블록·보행로·도로 단계) 틈으로만 보임 |
| 색 | 테마 토큰에서 유도한 역할 색(`--mini-<역할>`, 땅 = 강조색 16%) | 고정 hex(`--map-area` #d5dff3 등) — 강조색과 따로 놂 |
| 깊이 | 판: 그림자 → 옆면 → 윗면 → 안개 | 평면 |
| 선 | 진한 잉크 + 바탕색 테두리(`pings__case`) | 루트 `StopLines`에 테두리 없음 |
| 이름 | 바탕색 번짐 | 구역 이름 흐린 13px, 정류장 이름은 번짐 있음 |

데이터는 이미 있다: `public/korea/base`(4단계 타일, 땅·공원·도로 5등급), `koreaMapService.fetchBaseMap`, 그리고 **안 쓰이는** `hooks/useBaseMap.ts`(`ede3ccd`에서 본 지도에 넣었다가 행정구역 지도로 바뀌며 빠짐).

## 2. 무엇을 가져오고 무엇을 안 가져오나

| 미니맵의 것 | 본 지도 | 이유 |
|---|---|---|
| 색 역할(물·땅·공원·길·그림자) + 테마 토큰에서 유도 | **가져옴** (M1) | 같은 앱의 지도가 같은 색으로 읽혀야 함 |
| 물 = 땅이 없는 곳, 공원 녹색, 큰길 밝은 선 (Lynch) | **가져옴** (M2·M3) | 핵심. 본 지도에서도 강·공원·큰길이 사람이 아는 경계 |
| 행정 경계 그물 끄기 | **낮춤** (M4) | 본 지도의 구역 나누기(`focusLevel`, 구역 이름)는 따로 만든 기능이라 없애지 않고 옅은 틴트 + 가는 틈으로 — §6-1 결정 |
| 선 테두리(casing)·이름 번짐 | **가져옴** (M6) | 핀·선이 주인공(R1) |
| 판(옆면·그림자) | **변형해서** (M7, 선택) | 화면 전체를 판으로 만들 순 없음 → 가운데 범위의 구역(이미 계산하는 `alsoFocus`)만 살짝 떠 있는 판으로 |
| 공기 원근(안개) | 화면 위쪽 가장자리에만 아주 옅게 (M7, 선택) | 지도가 기울지 않았으니 약하게 — 안 해도 됨 |
| 실루엣 외곽선(쿠키 커터) | **안 가져옴** | 지도는 끝이 없음. 잘라 내면 끌 때 땅이 끊김 |
| 기울임(TILT)·거리 펴기·핀 떼어 놓기 | **안 가져옴** | 실제 좌표가 맞아야 하는 지도(길찾기 링크·핀 꽂기·조준선) |

## 3. 층 (아래에서 위로)

1. **물** — 화면 바탕(`--map-water` 역할). 국내 밖은 지금처럼 덮개(cover)가 가림.
2. **땅** — `BaseMap.land`, 단계별 타일(`koreaMapService`가 축척으로 고름). 작은 구멍(연못 부스러기)은 미니맵 `MIN_POND`처럼 화면 px 기준으로 메움.
3. **(선택) 떠 있는 판** — 가운데 범위의 읍면동: 옆면 + 흐린 그림자(M7).
4. **구역 색** — 지금의 `parts`(가운데 범위가 나뉜 조각)는 땅 위에 강조색 몇 % 얹은 **옅은 틴트**로만, `others`는 안 칠함(땅 그대로). 조각 사이 틈은 땅색 실선으로 **아주 가늘게**(1px 미만, 확대 깊으면 길 단계라 실제 길이 대신함).
5. **공원** — `BaseMap.parks`, 녹색 역할.
6. **길** — `BaseMap.roads`, 축척별 등급(`roadTierVisible`·`roadWidthPx` 이미 있음). 색은 땅보다 밝게(`--mini-road`처럼 `--surface`), 1등급만 살짝 진한 테두리. 미니맵은 1등급만 쓰지만 본 지도는 확대할수록 등급을 늘림.
7. **구역 이름** — 그대로, 바탕색 번짐 추가.
8. 핀·정류장·선(`StopLines`, 테두리 추가)·내 위치·그룹 핑 — 그대로.

## 4. 엔진별 방법

- **MapLibre**: GeoJSON 소스 + `fill`/`line` 레이어(물은 `background`, 땅·공원 `fill`, 길은 등급별 `line` — 폭은 줌 표현식으로 `roadWidthPx`와 같은 값). `refreshColors`가 새 레이어도 다시 칠함. 길 데이터가 크면 등급별로 소스를 나눠 줌에 따라 `setData`.
- **카카오**: 타일을 다시 칠할 수 없어 지금처럼 덮개 위에 SDK 객체를 얹음. 땅·공원은 `Polygon`(지금 `reshape`처럼 객체 재사용), 길은 `Polyline`. 객체 수가 성능의 전부라 **상한**(예: 면 300 · 길 400, 넘으면 작은 것·낮은 등급부터 버림)과 화면 밖 버리기. 그래도 끌 때 버벅이면 §6-2의 캔버스 오버레이 안.
- **계산 위치**: 땅·공원·길 고르기·단순화·구멍 메우기는 이미 있는 area worker(`services/areaMap.worker.ts`)에 넣어 행정구역과 **한 번에** 보냄(`AreaUpdate`에 `base` 추가) — 메인 스레드는 그리기만. `useBaseMap`은 지우거나 worker 경유로 바꿈.
- 지도 SDK 호출은 계속 `src/map/` 안에만(작업 규칙).

### M0 결과 (2026-10-20)

방법: `npm run shots -- mainmap` → `ui-shots/<폭>-mainmap-<곳>-<축척>.png`, 한 장으로 모은 것은 `ui-shots/mainmap-before.png`(375px)·`mainmap-before-desktop.png`(1280px). 곳은 성수(127.056, 37.544)·river(127.040, 37.535 — 한강 위)·종로(126.990, 37.5705)·양평(127.4875, 37.4917), 축척은 40·12·1.5 m/px(시군구·읍면동·블록 단계). 지도는 개발 때만 있는 `globalThis.__courseMap`(`map/createCourseMap.ts`)으로 `fitPoints`해서 옮김. 이 상태들은 위치 권한을 안 줌(앱이 '내 위치'로 옮기는 것이 맞춤 뒤에 와서 덮어썼음). 모두 MapLibre(이 PC의 헤드리스 Edge에서는 카카오가 5초 안에 안 떠서) — 카카오 기준은 M5에서 따로.

보이는 것(375px):
- **물이 없다**: river-dong·river-block에서 성수1가1동과 압구정동 도형이 한강 위까지 이어져 강이 땅색이다. 양평 블록에서는 남한강이 양평읍 안에 묻혀 있다. → M2·M3의 1순위.
- **경계 그물**: 시군구 축척은 회베이지 `others` 위 굵은 흰 틈이 화면 전체를 덮고, 파란 `parts`는 가운데 몇 구만. 읍면동 축척은 파란 동 조각 + 흰 틈. 미니맵의 R3가 지운 것이 여기선 화면의 주인공이다. → M4.
- **블록 축척은 거의 빈 면**: 성수·종로 블록은 큰 파란 조각 몇 개와 틈뿐, 길·공원이 없다(틈이 길을 대신하는데 모든 틈이 같은 굵기·색이라 큰길과 골목, 행정 경계가 구별 안 됨). → M3의 등급별 길.
- 공원(서울숲)·하천(중랑천·청계천)도 어느 축척에서나 안 보인다.

끌기 프레임(4× 느리게, 1초 끌기, 375px): 대개 25~55 frames/s, p95 17~180ms. 이 PC가 다른 일로 바빠서 같은 장면도 회차마다 2배쯤 흔들림 — M8에서는 같은 날 전/후를 번갈아 3번씩 재서 가운데 값으로 비교할 것.

찍는 법에서 배운 것(스크립트에 반영):
- 헤드리스에서는 4장에 1장꼴로 옛 화면(덜 그린·확대된 프레임)이 찍혔다. 앱 상태(가운데·줌·MapLibre CSS)는 맞았으므로 캡처 쪽 문제로 보고, 영역 소스가 3초 조용할 때까지 기다림 → 1px 오가는 이동 → `render`·`idle` → 버리는 캡처 한 장 → 진짜 캡처. 그래도 가끔 남아서 나쁜 장은 그 상태만 다시 찍음(데스크톱 yangpyeong-gu는 아직 옛 화면 — M8 전에 다시).
- 확인 필요(앱 버그일 수 있음): 앱 안 미리보기에서도 시군구 축척으로 맞춘 뒤 영역이 도착했는데 `triggerRepaint` 전까지 화면이 비어 있던 적이 한 번 있었다. 지도가 안 움직일 때 `setData`만으로 다시 그려지는지 M3에서 같이 본다.

## 6. 정할 것

1. **행정 구역 표시 세기** — ✅ 2026-10-20 결정: **옅은 틴트 + 가는 틈**(구역 나누기·이름 기능은 살리고 그물만 조용히). 다른 안: 완전히 끄고 이름만(미니맵과 똑같음, 대신 확대할 때 동이 나뉘는 느낌이 사라짐) / 지금 그대로(물·공원·길만 더함).
2. **카카오에서 그리는 방법** — 권장: **SDK 객체 + 상한**(지금 구조 그대로). 다른 안: 한 장 캔버스 오버레이에 직접 그리기(빠르지만 카카오 지도 이동과 맞추는 코드가 새로 필요, 확대 중 흔들림 위험).
3. **떠 있는 판(M7)** — 권장: 해 보고 M0 장면에서 보고 결정(시끄러우면 뺌).
4. **카카오 타일을 아예 가릴지** — 지금도 덮개로 가리고 있음. `BaseMap`이 있으면 카카오 타일은 끝까지 안 보이게 유지(권장) vs 블록보다 깊은 확대에서만 카카오 타일을 비춰 건물·상호를 보여 줌.

## 7. 하지 않는 것

- 본 지도 기울이기(pitch)·외곽선 자르기·핀 떼어 놓기·거리 펴기 (§2).
- 테마별 지도 색 — 지도는 언제나 기본(+ 다크) 테마라는 규칙 유지. 역할 색을 토큰에서 유도해 두면 나중에 바꾸기는 쉬움.
- 건물 하나하나, 지형 음영.
