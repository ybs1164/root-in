# 계획: 구획 안쪽을 블록·보행로 조각으로 (지도 4·5단계)

지금 지도는 화면 가운데 구역 하나만 한 단계 아래로 나눈다 (`src/domain/adminAreas.ts` `focusLevel`).

| 화면 축척 | 가운데 구역 → 나누는 단위 |
|---|---|
| 120m/px 이상 | 시도 → 시군구 |
| 8 ~ 120m/px | 시군구 → 읍면동 |
| 8m/px 미만 | 읍면동 → 구획 (도시 동 하나에 5~9개, 전국 23,432개) |

8m/px 아래로 더 확대하면 구획 하나(보통 수백 m)가 화면을 거의 채워서 지도가 큰 덩어리 몇 개로만 보인다.
**두 단계를 더한다** (2026-10-05 결정: 생활·서비스 도로로 블록, 보행로는 따로 한 단계):

| 화면 축척 | 가운데 구역 → 나누는 단위 | 자르는 길 |
|---|---|---|
| 2m/px 미만 (폰 폭 약 750m) | 구획 → 블록 | 생활·서비스 도로 |
| 0.7m/px 미만 (폰 폭 약 260m, B0에서 확인) | 블록 → 보행로 조각 | 보행로·산책로·계단·자전거길 |

주변은 지금 규칙 그대로 통짜로 그린다: 같은 부모의 다른 형제(같은 동의 다른 구획, 같은 구획의 다른 블록)와 이웃 읍면동.

작업 번호(B0, B1 …)로 참조한다. 한 번에 하나씩.

## B0. 크기·모양 먼저 재 보기 (코드 반영 전)
- `build_admin.py`에 블록 자르기를 넣어 **강남구(11680)·수원 권선구·농촌 군 하나**만 시험으로 만들어 본다. 블록 수, 파일 크기, 아주 작은 조각 비율을 기록한다.
- `scripts/area-preview.ts`로 역삼1동 구획 하나의 블록을 SVG로 뽑아서 눈으로 본다.
- 전국 크기를 추정한다. 지금 구획 데이터가 24MB이고 블록은 그 몇 배가 될 수 있다. 너무 크면 B1의 단순화·소수점 자리를 조정한다.

### B0 결과 (2026-10-05, 시험 스크립트로 4개 시군구)

| 시군구 | 구획 | 블록 (크기·중간 면적) | 보행로로 나뉜 블록 |
|---|---:|---:|---:|
| 마포구 | 117 | 360 (142KB · 2만㎡) | 46 / 360 |
| 강남구 | 196 | 650 (199KB · 1.7만㎡) | 51 / 650 |
| 수원 권선구 | 118 | 331 (129KB · 3.2만㎡) | 35 / 331 |
| 양평군 | 55 | 80 (255KB · 229만㎡) | 19 / 80 |

- 블록은 구획 하나에 약 3개, 도시에서는 실제 길 사이 블록 크기다. 2m/px 화면에서 볼 만하다 (역삼1동 SVG 확인).
- 블록 파일은 구획 파일의 약 3배라서 전국 약 65~70MB로 추정된다 (지금 구획 24MB). 100MB 안이라 읍·면도 포함한다.
- **보행로는 거의 나누지 못한다**: 인도(`sidewalk`)를 빼고 나면 OSM의 보행로는 대부분 막다른 길이라 면을 닫지 못한다. 주차장 통로·진입로까지 넣고 기준을 800㎡로 낮춰도 도시 블록의 8%만 나뉜다 (역삼1동은 70개 중 0개).
  → 보행로 단계는 **나뉘는 블록에서만** 들어간다: 보행로 파일에는 나뉜 블록의 조각만 담고, 가운데 블록이 안 나뉘면 0.7m/px 아래에서도 블록 단계 화면을 그대로 둔다.
- 시험: 보행로 조각에 쓰는 길 = 보행로 + `service=parking_aisle|driveway|drive-through`, 기준 800㎡ 또는 블록의 10%, 3,000㎡ 미만 블록은 자르지 않음. 도로 캐시 `data/korea/block-roads.pkl`(종류 `block`·`walk`·`minor`)은 이미 만들어 둠 (읽는 데 약 4분).

### B1·B1b 결과 (2026-10-05, 완료)
- 전국: 구획 24,225 · 블록 54,106 (57MB) · 보행로 조각 20,247 (37MB, 2,520개 읍면동). `public/korea/admin` 합계 약 115MB.
- 빌드 중 찾은 버그: 맞닿은 이웃이 없는 작은 조각(섬)을 합치지 못하고 버리고 있었다 — 구획부터 그랬다 (진도군 조도면은 육지의 81%만 덮였음). 섬은 따로 두도록 고침; 이제 블록이 덮는 면적은 모든 읍면동에서 99.8% 이상. 그래서 구획도 23,432 → 24,225개.
- 결정 (2026-10-06): 보행로 단계에서 `track`을 뺀다 (추천안). 다시 빌드한 결과: 블록 54,107 (51MB) · 보행로 조각 9,868 (13MB, 1,771개 읍면동), `public/korea/admin` 합계 **96.7MB** — 100MB 안이라 읍·면도 그대로 둔다.
- (이전) 합계 100MB 초과. 보행로 조각이 시험보다 커진 건 농촌의 `track`(농로)이 논밭을 잘게 나눠서다 (부안군 블록 262 · 조각 472). `track`을 빼거나 도시 동만 남기는 것 중 고른다.

## B1. 데이터: `public/korea/admin/block/<시군구>/<읍면동>.json`
- 자르는 도로: `residential`·`unclassified`·`living_street`·`service`(단 `service=parking_aisle|driveway|drive-through`는 뺀다 — 주차장·진입로가 아파트 단지를 잘게 쪼갬). 지금처럼 터널·`area=yes`는 빼고, 막다른 길은 자르지 않는다 (`cut()` 재사용, `polygonize`가 처리).
- 구획마다 `cut(section, local, min)`. 작은 조각 합치기 기준은 **5,000㎡ 또는 구획의 8%** 중 큰 쪽을 출발점으로 잡는다 (B0 결과로 조정).
- 이미 3만㎡보다 작은 구획은 자르지 않고 블록 하나로 둔다. 도로가 없는 농촌 구획도 블록 하나로 남는다.
- 파일은 **읍면동 하나에 하나**: 구획처럼 시군구 단위로 묶으면 확대 화면 하나 보려고 너무 큰 파일을 받아야 한다. 코드 `<읍면동코드>-<구획번호>-<블록번호>`.
- `LEVELS["block"]`: 단순화 약 0.00002°, 소수점 6자리, 최소 면적 2e-9 (B0에서 확인).
- `section-roads.pkl` 캐시에 생활·서비스 도로 구분을 넣는다 (캐시 형식이 바뀌니 버전을 올려 다시 만든다).
- `validate.py`/새 테스트: 블록을 합치면 원래 구획과 같다 (빈틈·겹침 없음), 코드 접두사가 그 구획이다.

## B1b. 데이터: 보행로 조각 (`walk/<시군구>/<읍면동>.json`)
- 자르는 길: `footway`·`path`·`pedestrian`·`steps`·`cycleway`·`track` + 블록에서 뺀 `service=parking_aisle|driveway|drive-through`. `footway=sidewalk|crossing`(차도와 나란한 띠만 생김)·실내·터널·`area=yes`는 뺀다.
- 3,000㎡ 이상 블록만 `cut()`, 합치기 기준 800㎡ 또는 블록의 10%.
- **나뉜 블록의 조각만 저장한다** (B0: 약 8%). 파일이 없거나 그 블록 조각이 없으면 블록 단계 화면을 그대로 둔다. 코드는 `<동>-<구획>-<블록>-<조각>`.

## B2. 서비스: `StaticAdminAreaService`
- `parseAreas`의 코드 정규식을 `^\d{1,10}(-\d{1,3}){0,3}$`로 넓힌다.
- `focusLevel`에 `'section'`(`SECTION_FOCUS_MAX_MPP = 2`)과 `'block'`(`BLOCK_FOCUS_MAX_MPP = 0.7`)을 더한다. `'block'`은 같은 방식으로 한 단계 더: focus = 가운데 블록, parts = 그 보행로 조각, others = 같은 구획의 다른 블록 + 같은 동의 다른 구획 + 이웃 읍면동.
- `'section'`일 때: 지금 `'dong'` 경로로 그 동을 찾은 뒤 `block/<시군구>/<동>.json`을 받는다. focus = 가운데 구획, parts = 그 구획 접두사의 블록, others = 같은 동의 다른 구획 + 이웃 읍면동 통짜.
- 블록 파일이 없거나(옛 배포) 받기가 실패하면 **조용히 `'dong'` 단계 결과**(구획 나누기)로 그린다. reject하지 않는 규칙 그대로.
- `adminAreaService.test.ts`: 2m/px 미만에서 블록 파일을 요청하는지, 없으면 구획으로 떨어지는지, 블록 코드 검증. `vi.stubGlobal('fetch')`.

### B2 결과 (2026-10-06)
- 다른 세션이 같은 때 지도를 "가운데 범위에 걸친 구역 전부"(`alsoFocus`, 최대 4개)를 나누도록 바꿔서, 새 단계도 같은 방식: 범위에 걸친 구획(최대 4개)을 블록으로, 범위에 걸친 블록을 보행로 조각으로.
- 블록 파일이 없는 구획·보행로 조각이 없는 블록은 그 자체를 통째로 그린다. 가운데 블록이 하나도 안 나뉘면 블록 단계 화면을 그대로 돌려준다.
- 이름: 같은 읍면동의 조각(나뉜 것·통짜)은 이름 하나 (`areaLabels.ts`가 구역 키로만 묶음, 나뉜 쪽 표시).
- 브라우저(MapLibre, 375px)에서 역삼1동 1.6m/px·신사동 0.5m/px 확인. 그리기 30~55ms, 첫 파일 받기 70~290ms.

## B3. 화면 처리
- `areaRenderWindow`의 재계산 조건은 가운데 구역 코드가 바뀌면 다시 그리므로 구획 코드로 그대로 동작하는지 확인만 한다.
- 2m/px에서 블록은 지름 25~75px 정도다. 지금 반지름(나뉜 구역 10px)·간격 4px가 작은 블록을 지우지 않는지 `area-preview`로 확인하고, 필요하면 `'section'` 단계에서만 반지름 상한을 낮춘다.
- 이름(`areaLabels.ts`): 블록·구획은 이름이 없다. 지금처럼 가운데에는 **읍면동 이름 하나**만 두고, 이웃 동 이름은 그대로. 블록마다 이름은 없다.
