```
┌──────────────────────────────┐
```

## P1 — 핀 즐겨찾기 (4~5일)

### P1.1 도메인 모델
```ts
// src/types/pin.ts
type PinIcon = 'cafe' | 'food' | 'bar' | 'photo' | 'shop' | 'stay' | 'nature' | 'star' | …; // lucide 아이콘 이름 매핑 12종
type PinColor = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8;                // --pin-N 토큰

interface PinCategory {
  id: string;            // 기본값은 'cafe' 등 고정 id, 사용자 추가는 uuid
  name: string;          // ≤ 12자
  icon: PinIcon;
  color: PinColor;
  parentId?: string;     // 세부 카테고리: '카페' > '디저트', '작업하기 좋은'
  order: number;
}

interface Pin {
  id: string; userId: string;
  place: PlaceRef;       // 스냅샷 (이름·주소·좌표) — CLAUDE.md 규칙
  categoryId: string;
  memo?: string;         // ≤ 120자
  visitedAt?: string;    // 체크인(P4.3)으로 생기면 채워짐
  createdAt: string;
}
```
- 세부 카테고리는 **2단계까지만** (대분류 > 세부). 세부는 부모의 아이콘을 물려받고 색만 바꿀 수 있다.
- 기본 카테고리 6개(카페·맛집·술집·사진 명소·쇼핑·가볼 곳), 세부는 비어 있음.
- 순수 함수 `domain/pin.ts`: `addPin`(같은 place.id 중복 방지 → 카테고리만 갱신), `movePin`, `validateCategory`, `categoryPath`(`카페 › 디저트`), `pinsByCategory`.
- 한도: 핀 500개, 카테고리 30개 (localStorage 용량 보호).

### P1.2 저장소 + 카테고리 관리
- `services/pinRepository.ts`: `PinRepository`, `PinCategoryRepository` 인터페이스 + localStorage `goodroot:pins:v1`, `goodroot:pin-categories:v1`
- 카테고리 삭제 시 소속 핀은 "미분류"로 (핀을 지우지 않음). 세부 카테고리 삭제 → 부모로.
- 설정 > 핀 카테고리: 추가/이름 변경/아이콘 12종 그리드/색 8칩/순서 위아래 버튼(드래그 없음).
- 위시리스트(`goodroot:wishlist:v1`)와의 관계: **별개 유지**. 위시리스트 = "하루 통째", 핀 = "장소 하나". 합치기는 M3에서 판단.

### P1.3 중앙 핀 버튼 — 핀 꽂기 흐름
1. 핀 버튼 탭 → **핀 꽂기 모드**: 지도 중앙에 고정 조준 핀 + 하단에 카테고리 칩 가로 스크롤(최근 사용 순)
2. 지도를 움직여 위치 맞춤 → 칩 하나 탭 = 즉시 저장 (한 번 더 확인 없음). "되돌리기" 토스트 4초
3. 이름: 조준 위치 근처 장소를 카카오 `coord2Address` / 주변 검색으로 채움, 실패하면 "지정한 위치". 저장 후 이름 수정 가능
4. 그 밖의 진입: 검색 결과 카드에 "📍 핀 저장" 버튼, 지도 **길게 누르기**(= M1 1.3, 우클릭·두 손가락 클릭은 뺌)
- `CourseMap`에 추가: `onLongPress(cb)`, `reverseGeocode`는 지도가 아니라 `services/placeSearch`의 `reverse(center)`로 (실패 시 `null`, reject 금지)

### P1.4 지도에 핀 표시
- `CourseMap.setPins(pins: PinMarker[])` — `{ id, center, color, icon, label? }`. 카카오는 `CustomOverlay`, MapLibre는 `Marker`, 공용 DOM은 `createMarkerElement` 확장(`variant: 'pin'`)
- 카테고리 필터 칩(시트 상단): 선택한 카테고리만 표시. 세부 카테고리 선택 시 부모 칩 아래 들여쓰기
- 핀 200개 이상이면 줌 아웃 시 점(dot)으로 축소 — 클러스터링은 M3 (카카오 `MarkerClusterer`는 CustomOverlay와 궁합이 나빠 보류)
- 핀 탭 → 장소 카드: 이름·카테고리 경로·메모, [카테고리 변경] [코스에 추가] [길찾기] [삭제]

## P2 — 핀 자동 선 잇기 (1.5~2일)

"핀을 고르면 알아서 동선이 이어진다." 실제 길찾기는 하지 않는다(직선 + 추정치, CLAUDE.md).

- `domain/routeOrder.ts` (순수 함수, 테스트 필수)
  - `orderByTime(stops)` — 체크인 시각이 있으면 시간순 (일일 루트 기본)
  - `orderByNearest(points, start?)` — 최근접 이웃 → **2-opt** 개선 (시작점을 고정하지 않으면 모든 시작점을 시도). 브루트포스 대비 오차 5% 이내를 8곳까지 테스트로 확인 (10곳 브루트포스는 테스트에 너무 느림)
  - `totalDistance(order)`
- 사용처
  1. 핀 목록에서 여러 개 선택(체크박스) → **"선으로 잇기"** → 최단 순서로 정렬된 코스 초안 생성 → 기존 CourseEditor로 넘어가 순서 수정·저장
  2. 카테고리 필터 켠 상태에서 "이 카테고리 잇기" 토글 → 지도에만 임시 선 표시 (저장 안 함)
  3. 일일 루트(P4)는 항상 시간순으로 자동 연결
- 시작점: 기본은 "현재 위치에서 가장 가까운 핀", 사용자가 첫 핀을 고정할 수 있음
- `CourseMap.setCourse`는 그대로 재사용. 임시 선은 `setGuideLine(points | null)`로 분리(스타일: 옅은 점선)

## P3 — 핀셋 공유 (2일)

- 핀셋 = **카테고리 하나(세부 포함) 또는 직접 고른 핀 목록** + 제목
- 링크 `#pins=<token>` (코스 `#share=`, 하루 `#diary=`와 별도). `services/pinShareService.ts`
  - 와이어 포맷 `v: 1` — `t` 제목, `c: [{i,n,ic,co,p?}]` 카테고리, `p: [{n,c,k,a?,m?}]` 핀 (k = 카테고리 인덱스). 좌표 소수 6자리
  - **최대 30핀, 토큰 6000자 이하** — 초과 시 메모 → 주소 순으로 잘라내고 안내. 30개 넘으면 "30개까지만 공유돼요"
  - 디코드 검증: 모양, 문자열 길이, 좌표 국내 범위(위도 33~39, 경도 124~132), 아이콘·색 enum 화이트리스트
- 수신 화면: 지도에 받은 핀(받은 색·아이콘 그대로) + 목록 → "내 핀에 모두 저장"(카테고리 이름이 같으면 합치고, 없으면 새로 만듦) / 개별 저장
- 공유 시트는 P5의 통합 시트 사용

## P4 — 달력 탭: 일일 루트 (3~4일)

기존 하루 기록(`DiaryEntry`, `goodroot:diaries:v1`)을 **데이터 그대로** 재사용하고 화면만 바꾼다.

- 기존 "기록 / ★ 위시리스트" 목록은 달력 아래 탭으로 유지

### P4.2 앱 안에서 일일 경로 지정 ("미래의 하루"도 가능)
- 과거·오늘뿐 아니라 **미래 날짜에도 루트를 짤 수 있음** → `DiaryEntry`에 `kind?: 'plan' | 'log'` 추가 (없으면 `'log'`로 간주 → 마이그레이션 불필요, 키 버전 유지)
- 추가 방법: 검색 / 핀에서 고르기(카테고리 필터) / "지금 여기"
- 계획 루트는 P2의 최근접 순서 제안 버튼 제공, 기록 루트는 시간순 고정

### P4.3 루트-인 (체크인)
- 오늘 화면에 큰 버튼 **"지금 여기 루트-인"** → 현재 위치 + 근처 장소 후보 3개(카카오 주변 검색) 중 선택 → 현재 시각으로 오늘 루트에 추가, 선 자동 연장
- 오늘 계획 루트가 있으면 가장 가까운 계획 스톱을 "방문함"으로 표시(계획 대비 진행률 `2/5`)
- 체크인한 장소는 선택적으로 핀에도 저장(토글, 기본 꺼짐)
- 위치 권한 거부·실패 → 토스트 + 검색으로 대체 (reject 금지)
- 백그라운드 자동 기록(위치 추적)은 **하지 않음** — 웹에서 불가능하고 배터리·개인정보 부담

## 구현 메모 (2026-09-29)
계획과 달라진 점, 해 보고 알게 된 점.
- **하단 바 탭**: 달력·추천 버튼을 한 번 더 누르면 핀 홈으로 돌아간다. 가운데 핀 버튼은 누르면 곧바로 핀 꽂기 모드로 들어가고 핀 홈으로 이동한다 (기본안 그대로). 핀 꽂기 모드는 핀을 하나 꽂아도 유지되어 연속으로 꽂을 수 있고, X나 핀 버튼으로 끝낸다.
- **데스크톱**: 하단 바를 세그먼트 탭으로 바꾸지 않고 왼쪽 패널 아래에 그대로 붙였다. 구현이 단순하고 모바일과 조작이 같다.
- **핀 아이콘은 이모지**: 두 지도 구현 모두 마커를 React 밖의 DOM으로 그려서, React 아이콘(lucide)을 쓰면 마커와 목록의 모양이 달라진다. 이모지 12종이면 양쪽이 같다. OS마다 모양이 조금 다른 점은 감수한다.
- **`CourseMap` 변경**: 계획했던 `setAimMode`는 넣지 않았다. 조준 핀은 지도 위에 올린 DOM 오버레이이고, 위치는 `getCenter()`로 읽는다. 대신 `fitPoints`와 옵션 `onPinClick`·`onLongPress`를 추가했다.
- **길게 누르기 (M1 1.3)**: 누른 지점에 장소 카드가 뜬다 (이름은 역지오코딩으로 채움). 카드에서 [📍 핀]으로 핀을 꽂거나 [N번째로 추가]로 코스나 하루 루트에 넣는다.
- **장소 검색 인터페이스**: `reverse(center)`(핀 이름 짓기)와 `nearby(center)`(루트-인 후보 3곳)를 추가했다. 카카오는 `Geocoder.coord2Address`와 `categorySearch`(카페·음식점·관광명소·문화시설, 120m 안), Photon은 `/reverse`(도로·행정구역 제외, 150m 안). 둘 다 실패하면 `null`이나 `[]`를 돌려주고 reject하지 않는다.
- **일일 루트 모델**: 날짜마다 기록 하나를 두고 `kind: 'plan'`으로 계획을 표시한다. 계획의 스톱에는 `checked`가 있다. 루트-인 위치가 체크하지 않은 계획 스톱에서 150m 안이면 그 스톱을 체크하고, 아니면 방문한 스톱으로 뒤에 추가한다. 오늘은 기록과 계획 중에서 고를 수 있고, 미래 날짜는 계획만, 지난 날짜는 기록만 된다. 하루 공유 링크에는 선택 필드 `p: 1`을 더했다 (이전 버전 디코더는 이 필드를 무시하고, `p`가 없는 링크는 기록으로 열린다).
- **추천 탭**: 항목을 누르면 `#share=`나 `#pins=` 해시를 설정해서 받은 링크와 같은 화면·검증·저장 흐름을 그대로 쓴다.
- **디자인 테마 삭제 (2026-09-29)**: 3안 전환 기능을 만들었다가 사용자 결정으로 모두 걷어냈다. 색은 원래의 `:root` 토큰 한 벌(라이트/다크)만 남았다.
- **앱 이름 root-in**: 로고는 i 글자 전체를 지도 핀으로 바꾼 워드마크다. 핀 머리가 i의 윗부분이 되고 핀 끝이 기준선을 찍는다. SVG로 그려서 폰트와 상관없이 같은 모양이다. 저장소 키 `goodroot:*`는 데이터 호환을 위해 그대로 둔다.
- **색 규칙을 테스트로 보장**: `src/test/styles.test.ts`가 `styles.css`에서 `:root` 토큰 블록 바깥에 색 리터럴이 없는지 검사한다. 이를 위해 `vitest.config.ts`에서 `styles.css`만 CSS 처리를 켰다.
